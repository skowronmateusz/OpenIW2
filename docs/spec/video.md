# Cinematics (video/*.roq)

Everything here is read from CoD2SP_s.exe and the shipped files; guesses are marked TODO(spec).

## File format (RoQ)
- Movies are `video/<name>.roq` in the iwds (iw_06, localized iwds for the subtitled ones). Header: `0x1084`, `0xFFFFFFFF`, fps u16. Then chunks: id u16, size u32, argument u16, body.
- `0x1001` info (width, height, 8, 4); `0x1002` codebook (argument high byte = 2x2 cells, low byte = 4x4 vectors; a cell is 4 luma + U + V); `0x1011` VQ frame (argument = motion offset; 2-bit codes 0 unchanged, 1 motion, 2 vector, 3 split, most significant bits first); `0x1020` / `0x1021` DPCM sound (22050 Hz, mono / stereo, signed square steps from a predictor in the argument); `0x1030` signature (ignored).
- Decoder: `src/video/roq.{h,cpp}` (clean-room, test `tests/test_roq.cpp`); `iw2roq <main> <movie> info|frames <dir> <n>...` inspects / dumps frames (atvi and iw_logo are 512x512 @ 30 fps, stereo).

## How the game plays them
- Script builtin `cinematic(name [, exitTime])` (table 0x5a622c, function 0x4f4220): stores the name (63 characters) at 0x1c60ff4 and the exit time in seconds (a negative value is a script error 0x586138; stored in ms at 0x1c60fec, it is shared with `changelevel(map, persistent, exitTime)`), sets the request flag 0x1c60fe0 and the movie-pending flag 0x1c60fe4. `changelevel` (0x4f3f00) sets 0x1c60fe0 as well; `missionsuccess` (0x4f4040) calls it and sets only 0x1c60fe4.
- The request is handled by 0x4d9da0 (called from 0x4d9f90): with a live player it sends the client `scr_fade 1 <now+250> <exit+750>` (fade to black) and `snd_fade 0 <exit+1000>` and schedules the change at now + exit + 1000 ms (0x1c60f54).
- When it falls due (0x4d9f90): with the pending flag and a name it runs `cinematic <name> 0`; with the flag and no name `openvictoryscreen` (missionsuccess without a cinematic); without the flag `loadgame_continue` (after a death) or the level load (0x4d9f00). The movie's end continues the load (0x49db20 -> 0x4d9f00, also when the cinematic cannot be opened).
- `_briefing.gsc` `gotothelevel` calls `cinematic(movie)` for every slide with a movie, then `changeLevel(levelToLoad)`; `_endmission.gsc` plays `cinematic("movie_victory", 2)` then `missionSuccess("credits")`; the `movie_*` maps are briefing maps with a single movie slide.
- Console commands (0x40e6ff..): `cinematic` (0x403010: skippable byte 0x59a0d0 = 1) and `unskippablecinematic` (0x403020: byte = 0), both into CL_PlayCinematic_f (0x49e690): argument 1 the name, argument 2 flag characters: '1' system (bits 5), '2' |2 loop (the movie restarts at its end, 0x49ded8), '3' |0x20 letterbox (rectangle y 105, height 270 of 640x480, otherwise 0,0,640x480). Bit 0 = system: closes the menus and sets the client state 0x5d5680 = 1. Scripts always give `0`.
- Skippable movies stop on a key or mouse button; stopping or ending a movie runs the `nextmap` dvar when the previous state was 0 (this is how the start-up chain proceeds).
- Clock (0x49dcc0): wall time since start; a frame delta over 100 ms moves the start time (the movie freezes through hitches); the frame shown is elapsed * fps / 1000, late frames are decoded and dropped (0x49de50 loop); bit 4 would use the sound clock (not set by the command). Audio is queued when its frame is decoded.
- Start-up (Com_Init 0x42dee0, 0x42e7d5): `unskippablecinematic legal` (no legal.roq ships here), and while `com_introPlayed` (archived, default 0) is 0: `cinematic atvi; set nextmap "cinematic IW_logo; set nextmap cinematic cod_intro"`. Nothing in the exe writes com_introPlayed (only a config can).
- Subtitles: the chunk statistics of atvi, movie_africa and cod_intro show only the chunk types 0x1001, 0x1002, 0x1011 and 0x1021, so there is no subtitle track in the files, and the exe's cinematic code has no text path; the narration is inside the movie audio. Sound alias subtitles belong to sound aliases only.

## openiw2
- VM: `cinematic` stores the name (`World::takeCinematic()`) and the exit time; `changelevel` / `cinematic` schedule the change at exit + 1000 ms and send `scr_fade` / `snd_fade`; iw2view fades the screen (`src/game/screenfade.h`, 0x4bda70: alpha steps by real dt / duration, drawn over the HUD) and plays the movie before the next map loads.
- Playback (iw2view): modal, 640x480 area centred, key / mouse button skips (skippable ones), letterbox and loop supported, audio on its own 22050 Hz stream, wall clock with frozen hitches and dropped late frames as above. `--shot` never plays movies.
- Front end (`--menu`): plays legal (if present, unskippable), atvi, IW_logo, cod_intro unless `--no-intro` or env `IW2_SKIP_INTRO` (com_introPlayed has no source here).
- Sync measurement (`IW2_CINEMATIC_STATS=1`, macOS, default output device): picture time minus the audio actually played by the stream (samples put minus queued; SDL pulls in ~80 ms chunks) after the first second: atvi mean 58 ms (35..80), movie_africa 64.7 s mean 29 ms (4..475, one hitch), no dropped frames; the sound lags the picture by about one to two frames plus the device latency. The original does not sync to audio either (wall clock).
- Not done: the `openvictoryscreen` path of `missionsuccess` without a cinematic (UI), the client state 0x5d5680 effects, the dvar 0x1c148c4 that disables requests, a console command to start a movie (use `IW2_PLAY_CINEMATIC`).
