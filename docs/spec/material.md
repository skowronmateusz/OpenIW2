# Materials and lightmaps

Sources: static analysis of `gfx_d3d_x86_s.dll` (v1.0) with REA 6.7.0 + Ghidra 12.1.4, checked against the
shipped `materials/*` files and the game's own shader sources (`materials/shaders/lib/*.hlsl`).

## Material file (`materials/<name>`, binary, little endian)

Loaded through `materials/%s` (`FUN_1001c7a0`) and fixed up in `FUN_1001c540`.
Every offset field is relative to the start of the file and is turned into a pointer at load time.

| Offset | Type | Field | Status |
|---|---|---|---|
| 0x00 | uint32 | offset of material name | observed (relocated) |
| 0x04 | uint32 | offset of a second name (the reference image; equals the colorMap image in the samples) | relocated; meaning inferred |
| 0x08–0x33 | – | sort key, blend/state bits, surface flags | not decoded |
| 0x34 | uint16 | texture count | observed (loop bound) |
| 0x36 | uint16 | constant count | observed (loop bound) |
| 0x38 | uint32 | offset of technique-set name (`materials/techniquesets/<name>.techset`) | observed |
| 0x3c | uint32 | offset of the texture table | observed (relocated) |
| 0x40 | uint32 | offset of the constant table | observed (relocated) |

Texture entry (12 bytes):

| Offset | Type | Field |
|---|---|---|
| 0 | uint32 | offset of the sampler name (`colorMap`, `detailMap`, `normalMap`, `specularMap`, …), hashed at load time |
| 4 | uint8 | sampler state (inferred) |
| 5 | uint8 | semantic: 2 = color (also used by `detailMap`), 3 = normal, 4 = specular, 5 = water. These values are compared in the loader; the names come from the data |
| 6 | uint16 | padding (always 0 in samples) |
| 8 | uint32 | offset of the image name (`images/<name>.iwi`). For semantic 5 it is an offset to a water description instead |

Images whose name starts with `$` are built-in (generated by the engine, for example `$white`).

Constant entry (20 bytes): `uint32 nameOffset; float value[4]` (for example `detailScale = 8 8 0 0`).

## Lightmaps (lump 1 of `.d3dbsp`)

Each 4 MiB lightmap holds four images back to back. Their sizes come from `FUN_10001ff0`:

| Part | Size | Bytes/px | Shader sampler (from `globals.hlsl`, `lightmap.hlsl`) |
|---|---|---|---|
| 0 | 512 × 512 | 4 (B,G,R,A) | `lightmapSamplerR`: 4 lighting coefficients for red |
| 1 | 512 × 512 | 4 | `lightmapSamplerG` |
| 2 | 512 × 512 | 4 | `lightmapSamplerB` |
| 3 | 1024 × 1024 | 1 | `lightmapSamplerSun`: sun visibility |

The game's shader computes `lightmapDiffuse.c = dot(coeffs_c, weights)`. Here `weights` is sampled from the
engine-generated `$lightmapweights` texture at the normal-map sample. The texture is built in `FUN_1000d5c0` /
`FUN_1000d260`; its contents are **not specified yet**. Sun light is then added as `sunVisibility × phong(sun)`.

When `r_optimizeLightmaps` is 2, the renderer instead merges the lightmaps into one RGBA image per lightmap,
built from part 0.

Lightmap index 31 on a triangle soup means "no lightmap".
